The spec

One page. No marketing.

The full one-page credential spec lands here before anything launches. Written for builders, not marketers. Below is exactly what it will cover.

  1. Issuance

    How an issuer creates a credential: the fields it carries (agent identifier, issuer identity, public key, capabilities, expiry), how it is signed, and how an issuer publishes its public key. Permissionless: anyone can be an issuer.

  2. Presentation

    How an agent presents its credential to a merchant: the transport, the handshake, and what the merchant receives. Designed to sit alongside existing traffic, not replace it.

  3. Verification

    How a merchant checks a credential: signature validation, issuer recognition, expiry, and revocation lookup. The verifier returns a signed yes or no in under a second. Free, forever.

  4. Revocation, on page one

    How an issuer revokes a credential and how verifiers learn about it, including the honest limits: propagation delay and the corners of revocation at scale that are not solved yet. Stated plainly, not buried in an appendix.

  5. Neutrality pledge

    No favored agent platform. No exclusive issuance deals. The verifier treats all issuers by the same rules. Neutrality is a design constraint from day one. Read the full pledge.

  6. Attestation, not a guarantee

    The spec's language contract: verification attests to identity only. No wording in the spec, the verifier, or any integration may imply that a verified agent is safe, honest, or trustworthy.

Appendix: threat model

A written threat model ships with the spec before any prototype touches real keys: what the system protects against, what it explicitly does not, and who bears the loss when a credential is compromised. The demo below uses clearly fake credentials until that work is done.
