The credential spec

Test draft. Not a standard. Not production. Everything here will change.

Revocation comes first

A credential is only useful if it can be taken away. The issuer keeps a signed list of revoked credentials. The verifier checks the list on every check and rejects anything on it.

Honest gaps in this draft: there is no live status check yet, no limit on how old a cached list can be, and no plan yet for a compromised issuer. Do not build production on this draft.

Attestation, not a guarantee

We verify identity. We do not vouch for behavior. A passing check means “this agent is who it claims to be.” It never means “this agent is safe.”

There is no badge, checkmark, or seal. Do not describe a passing check as an endorsement.

Neutral by design

No favored agent platform. No exclusive deals. Any builder can issue credentials under this spec, and the verifier treats every issuer the same.

The verifier is free, and it stays free. If this ever becomes infrastructure, it only works if it is neutral, so neutrality is a design constraint now.

What a credential carries

  • The agent: an id, a name, and who operates it.
  • The issuer: an id and a name.
  • Issued and expiry times. Expired credentials are rejected.
  • Scope. In this draft: demo verification only.
  • A signature over the whole thing.

How a check works

  1. Confirm it is a test credential.
  2. Check the signature against the issuer’s public key.
  3. Reject it if it has expired.
  4. Reject it if it is on the revocation list.

All four must pass.

What it does not stop

A stolen key used before revocation spreads. A compromised issuer. An agent that is correctly identified but behaves badly. Identity is not behavior.

Who bears the loss when a credential is stolen is undecided. It will be written before any real pilot.
